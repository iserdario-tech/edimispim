# Как участвовать

Спасибо, что заглянул. Проект маленький и личный, но правила в нём настоящие: они появились из набитых шишек, а не из шаблона.

## С чего начать

- Прочитай [README](README.md) и [FAQ](docs/FAQ.md): там ответы на большинство «почему так».
- Открой [LAB.md](LAB.md): это журнал всех волн. Прежде чем предлагать идею, поищи её там: возможно, она уже пробовалась и отклонена с причиной.
- Запусти локально: `npm ci --legacy-peer-deps && npm run dev`, тесты `npm test`.

## Что можно принести

- **Баг** → [issue по шаблону](https://github.com/iserdario-tech/edimispim/issues/new/choose) с датой, экраном и, если есть, скриншотом. Копия данных помогает воспроизвести, но присылай её только если в ней нет ничего личного.
- **Идею** → issue «Идея». Хорошая идея проходит три сита: её нельзя сделать отдельно в приложении про сон или отдельно в приложении про еду (переплетённость), у неё есть основание в данных и формулировка не обещает большего (научная честность), она влезает в текущие модули без переписывания половины кода (цена).
- **Рецепт** → черновик в `scripts/drafts/` по образцу `wave-t.ts` и пулл-реквест. Состав в граммах, шаги своими словами, ссылка только на страницу, с которой выписан состав.
- **Исправление** → пулл-реквест с тестом.

## Правила кода

1. **Логика без React.** Всё, что считает, живёт в `src/*.ts` или `src/food` как чистые функции с тестами. Экраны только рисуют.
2. **Тест вперёд кода** для новой логики: слово дня, личный эффект, серия, планировщик. Для правки планировщика дополнительно `npx vite-node scripts/audit-planner.ts` до и после, цифры в описание.
3. **Один порог на всё приложение.** Если число (четыре ночи, 10 минут, ±3 %) используется в двух местах, оно живёт в одном месте с комментарием, откуда взялось.
4. **Комментарий объясняет «зачем», а не «что».** Хороший комментарий в этом репозитории начинается с ситуации из жизни («нужно 100 г творога, а пачка 200») и заканчивается тем, что из-за этого сделано иначе.
5. **Совместимость данных.** В `StoredState` только необязательные поля. Старая копия обязана открыться.
6. **Честная рамка.** Оценки со знаком «≈». «Связано», а не «приводит». Никаких баллов, красного цвета, процентов и p-значений там, где это наблюдение. На это есть тесты, и они должны остаться зелёными.
7. **Слова вместо терминов.** «Время подъёма», а не «якорь»; «клетчатка», а не «клетч»; «Ем без плана», а не «читмил»; «вес стоит», а не «плато». Полная таблица в спеке 2.0, §8.
8. **Бесплатные тарифы.** Любая новая запись в KV, лишний абзац в промпте коуча или запрос к магазину стоит чьих-то вопросов в день. Считать до того, как писать.

## Проверка перед пулл-реквестом

```bash
npm run typecheck && npm test && npm run build
```

Если менялся интерфейс: посмотреть экран на 375 px в светлой и тёмной теме и, для «Суток», в три времени суток (утро, день, вечер). Если менялся воркер: `cd worker && npm run dry`.

## Коммиты

На русском, одной строкой о сути: «Волна 52: день без готовки на двоих, порции свои у каждого». Если волна большая, подробности идут в LAB.md, а не в сообщение коммита.

## Как устроена волна

1. Тема: одно из четырёх направлений — механики связи сна и еды · понятность · надёжность · контент.
2. Десять идей без фильтра.
3. Отбор по трём ситам (см. выше).
4. Реализация одной-двух лучших с тестами.
5. Проверка совместимости: все тесты, typecheck, сборка, экраны на телефоне.
6. Коммит одной волной и запись в LAB.md: повод, что сделано, замеры, грабли, что отклонено и почему.

Отрицательный результат тоже результат: он не даст вернуться к той же идее через десять волн.
